# Change hygiene

A live game learns nothing from a fortnight in which five things shipped at
once.

| Rule | Why |
| --- | --- |
| Never ship an economy change and an event on the same day | Unless you are content to learn nothing from either |
| One open trial per system | Two changes to the same economy loop cannot be told apart afterwards |
| Every change records spend, retention **and** sentiment | Economy changes rarely move only the metric they aimed at |
| Check what is live before scheduling | Overlapping events are two events each performing worse than either alone |
| Check the population before the product | A UA campaign bringing cheaper users moves every metric with no product change |

When a metric moves, read `economy-changes` and `events` before theorising.
"Confounded, and here is the schedule that would separate them" is an honest
and frequently correct answer. See the [[LiveOps calendar]] and
[[Monetization principles]].
