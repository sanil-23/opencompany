# Build honesty

The characteristic failure of game production is a feature list that says "in"
for a hundred things that are technically present and not yet fun, and a
schedule built on that list.

| Rule | Why |
| --- | --- |
| `playable` says what actually works, in plain words | "In" and "fun" are different states, and conflating them is how a project slips at the end |
| Play the build before describing it | Every claim about how the game feels is checkable in ninety seconds |
| A cut feature closes with its reason | The same feature is proposed again every project |
| `depends_on` is filled in | Games fail at the seams between systems, not inside them |
| Marketing shows the build | A rendering of what the build will be is a promise somebody has to keep |

"In, but rough" is a status because it is the honest state of most of a game
most of the time. See [[Design pillars]] and the [[Playtest discipline]].
